# Prescription: GPL-Clean BackImage Trajectory-Table Observer

## Purpose

Implement the BackImage trajectory-table observer described in the local README. This is the next step after the Vernier observer produced an interpretable null: Vernier sign evidence can wash out under pose marginalization, so the more appropriate diagnostic is whether natural-image structure helps constrain unknown fixational motion while preserving image or patch identity.

The core question is:

```text
Given a V1-twin response to a natural image patch under unknown fixational motion,
can a likelihood observer identify the image patch while marginalizing trajectory
as a nuisance variable?
```

This is not yet a full natural-image prior in the Wu sense. It is a finite discrete image-candidate prior combined with a finite discrete trajectory prior.

This is also not a compact-geometry observer. The BackImage trajectory-table
observer uses exact cached V1-twin responses for every finite image-candidate
and trajectory-candidate pair:

```text
lambda_counts[I_i, tau_k, time, unit]
```

The `empirical`, `OU`, or matched-null prior is the nuisance trajectory prior
`p(tau_k)`, not a learned image prior. Candidate images are hypotheses in a
finite choice set with an implicit uniform prior unless explicitly reweighted.

Do not describe this branch as using:

```text
compact translation basis
instantaneous local chart
lag-linear geometry approximation
full Wu-style image reconstruction
continuous natural-image prior
```

A later compact-geometry branch can test whether a low-dimensional or lagged
translation approximation preserves the same joint-eye rescue demonstrated by
the exact response table.

## Wu-Inspired Design Lessons To Use

The useful ideas from the Wu-style pipeline are conceptual, not code-level:

- Always compare matched `known-eye`, `zero-eye`, and `joint-eye` observers.
- Treat eye trajectory as a nuisance latent variable.
- Use the same likelihood convention across all observer conditions.
- Tune or at least expose a likelihood/trajectory-posterior temperature.
- Record trajectory posterior diagnostics, not only final image accuracy.
- Keep known-eye and zero-eye baselines as fixed-trajectory controls.
- Start with a small, auditable smoke run before scaling up.
- Avoid pulling in the full image reconstruction, denoiser, or EM machinery for this pilot.

For this BackImage branch, we do not reconstruct the image. We score a finite table of candidate image patches and candidate trajectories.

## Mathematical Target

Let:

- `I_i`: candidate natural image patch/window.
- `tau_k`: candidate trajectory from a finite trajectory catalog.
- `y_obs[t, u]`: observed expected-count or spike-count response for one generated trial.
- `lambda[i, k, t, u]`: V1-twin expected count response for image `I_i` rendered under trajectory `tau_k`.

The joint-eye observer should score image identity by marginalizing trajectory:

```text
log p(y_obs | I_i)
  = log sum_k p(y_obs | I_i, tau_k) p(tau_k)
```

For a uniform trajectory catalog:

```text
joint_score[i] = logmeanexp_k log_likelihood[i, k]
```

If the trajectory catalog has nonuniform prior weights:

```text
joint_score[i] = logsumexp_k (log_likelihood[i, k] + log_prior_tau[k])
```

The first implementation should use deterministic expected-count observations unless the existing project already has a clean sampled-spike convention for this branch.

Recommended Poisson score:

```text
lambda_safe = maximum(lambda_i_k, eps)
log_likelihood[i, k] =
  sum_t,u y_obs[t, u] * log(lambda_safe[t, u]) - lambda_safe[t, u]
```

The observation-only `-log(y!)` term may be omitted because it is constant across candidates for a fixed trial.

Do not use candidate-dependent Gaussian log determinants as the default for this deterministic expected-count observer.

## Observer Definitions

For each observed trial generated by true image `I_true` and true trajectory `tau_true`, compute:

### Known-Eye

```text
known_score[i] = log p(y_obs | I_i, tau_true)
```

This is the upper-bound fixed-trajectory observer. It must use the exact same response table and likelihood convention as the other observers.

### Zero-Eye

```text
zero_score[i] = log p(y_obs | I_i, tau_zero)
```

Primary zero convention:

```text
static image rendered at the same selected BackImage patch/window center,
with tau(t) = 0 for all t
```

Do not silently mix this with screen-centered, trace-mean, initial-pose, or per-candidate static conventions. Those can be added later, but each must be explicitly labeled.

### Joint-Eye

```text
joint_score[i] = logsumexp_k(log_likelihood[i, k] + log_prior_tau[k])
```

For uniform trajectory prior:

```text
joint_score[i] = logmeanexp_k(log_likelihood[i, k])
```

The predicted image for each observer is:

```text
argmax_i observer_score[i]
```

Report rank and margin, not only top-1 accuracy.

## Key Difference From Vernier

The Vernier pilot asked whether pose marginalization preserves a tiny binary Vernier-sign signal. The BackImage observer should instead ask whether the natural image itself makes the trajectory posterior nonuniform enough that marginalization remains useful.

This means the main scientific diagnostic is not just:

```text
joint_eye_accuracy > zero_eye_accuracy
```

It is also:

```text
p(tau | y_obs, I_true) concentrates relative to the catalog prior
```

If known-eye is high but joint-eye equals zero-eye and trajectory posterior remains nearly uniform, that is a real result.

## Additional Guardrails After Vernier Trajectory-Table Results

The Vernier trajectory-table observer showed that known-eye scoring can be informative while nuisance marginalization fails because the trajectory posterior remains diffuse. Therefore, this BackImage observer must explicitly distinguish three questions:

1. Does the response contain image information when the trajectory is known?
2. Does the trajectory likelihood localize the true or nearest trajectory?
3. Does marginalizing over a non-leaky trajectory prior preserve image evidence?

To support this, every run must separate the trajectory used to generate the observation from the trajectory catalog used as the nuisance prior.

Required condition fields:

```text
observation_condition
observation_family
observation_scale
prior_condition
prior_family
prior_scale
trajectory_prior_mode
```

Required `trajectory_prior_mode` values:

```text
include_self
leave_one_out
```

`include_self` is a diagnostic upper-ish table-lookup condition. Scientific interpretation should rely on `leave_one_out` or another non-leaky prior mode.

The cross-prior matrix should be available from the beginning:

```text
observed empirical x prior empirical
observed empirical x prior OU
observed empirical x prior shuffled-position
observed OU x prior empirical
```

Promote the best-single-trajectory diagnostic and marginalization dilution gap
to primary readouts. For each image trial, report:

```text
known_eye
zero_eye
joint_eye
best_single_tau
joint_vs_best_single_tau_gap
posterior_N_eff
nearest_tau_rank
```

The best-single-trajectory diagnostic is the image score obtained by selecting
the single trajectory in the prior catalog that gives the largest likelihood
for that image. It is not a biologically plausible observer and is not a strict
oracle upper bound on image-identity accuracy, because single-trajectory
maximization can overfit distractor images. It is a diagnostic for whether
useful trajectory-specific evidence exists before marginalization.

Interpretation matrix:

```text
known high, best single-tau high, joint low, N_eff high:
  useful trajectory-specific evidence exists, but marginalization dilutes it.

known high, best single-tau low, joint low:
  the trajectory catalog lacks support for the observed response or the likelihood model is mismatched.

known high, joint high, N_eff low, nearest trajectory rank good:
  natural-image structure supports useful pose marginalization.

known high, joint high, N_eff low, nearest trajectory rank poor:
  posterior concentrates, but not on the correct motion; inspect image-identity or gain confounds.
```

Posterior concentration is not sufficient by itself. A successful joint observer should concentrate posterior mass near the true or nearest plausible trajectory, not merely become nonuniform.

## Posterior Diagnostics

For each observed trial and each candidate image, compute:

```text
log_p_tau_given_y_i[k]
  = log_likelihood[i, k] + log_prior_tau[k]
    - logsumexp_k(log_likelihood[i, k] + log_prior_tau[k])
```

Then compute:

```text
N_eff = 1 / sum_k p_tau[k]^2
entropy = -sum_k p_tau[k] log p_tau[k]
max_posterior_tau = max_k p_tau[k]
best_tau_index = argmax_k p_tau[k]
true_tau_rank
nearest_tau_rank
best_single_tau_score
joint_vs_best_single_tau_gap
```

Definitions:

- `true_tau_rank`: rank of the exact generating trajectory if it exists in catalog.
- `nearest_tau_rank`: rank of the catalog trajectory nearest to the true trajectory under a declared distance.
- `best_single_tau_score`: `max_k log_likelihood[true_image, k]`.
- `joint_vs_best_single_tau_gap`: `best_single_tau_score - joint_score[true_image]`.

Recommended distance metrics for nearest trajectory:

- raw eye-coordinate RMSE over time;
- retinal displacement RMSE over time;
- response-space distance under the true image;
- rendered movie/patch distance if cheap enough.

The primary trajectory-localization metric should be nearest-trajectory rank, not exact true-trajectory rank, because finite catalogs can contain close surrogates.

## Candidate-Set Difficulty Ladder

Implement the experiment so the difficulty can be dialed up:

1. `self_lookup`: candidate set contains the exact true patch and trivial distractors. Used only for sanity checks.
2. `random_global`: easy, likely high image separability. Smoke test only.
3. `same_session_region`: removes some trivial session/position cues.
4. `matched_structure_bins`: tests whether decoding survives low-level feature matching.
5. `hard_negative_structure`: nearest neighbors in feature space, excluding duplicates.
6. `matched_static_response`: hard negatives matched by stabilized twin response, population mean rate, or covariance-whitened static response distance.

Do not draw scientific conclusions from `self_lookup` or `random_global` alone.

## Critical Code-Review Risks

A reviewer should specifically check:

- Are `known`, `zero`, and `joint` using the same `y_obs`, candidates, units, binning, and likelihood?
- Is the zero trajectory definition fixed and recorded?
- Is `joint_score` a true log-sum/log-mean over trajectories, not a best-trajectory score?
- Is the trajectory prior included exactly once?
- Are observation condition and prior condition recorded separately?
- Is `include_self` separated from `leave_one_out`, and are scientific claims based on non-leaky priors?
- Are `logsumexp` and `logmeanexp` numerically stable?
- Are response tables indexed `[candidate, trajectory, time, unit]` consistently?
- Does the true image appear exactly once in every candidate set?
- Are duplicate/near-duplicate patches detected?
- Are static-response, mean-rate, and contrast distances recorded for hard-negative controls?
- Are posterior diagnostics computed for the true image and optionally for all candidate images?
- Does posterior concentration occur near the true or nearest trajectory, not merely somewhere in the catalog?
- Are best-single-trajectory and dilution-gap diagnostics reported as primary readouts?
- Is the likelihood scale recorded and applied consistently?
- Is likelihood scale predefined or validated separately, rather than selected by final test accuracy?
- Are Stage 1 and Stage 2 outputs deterministic under a fixed seed?

## Acceptance Criteria

The first implementation is acceptable when:

- It implements finite-table known/zero/joint image identity scoring.
- It writes trial-level, summary, posterior, cache-manifest, and metadata files.
- It includes Stage 0 and Stage 1 commands that complete quickly.
- Stage 1 includes self-lookup and known-vs-zero sanity checks.
- It reports trajectory posterior concentration metrics, especially `N_eff / N_catalog`.
- It reports whether posterior concentration is near the true or nearest trajectory.
- It reports the best-single-trajectory diagnostic and joint-vs-best-single-tau gap.

- It includes at least one nontrivial hard-negative candidate set, preferably `matched_static_response`, before making interpretive claims.
- It does not copy or adapt GPL-covered source code.
