# Unified Feature Observer Score Decision

Date: 2026-07-05

Status: adopted scoring decision for the draft1 Figure 4 rewrite.

## Decision

Use held-out normalized MSE, reported as cross-validated `R2_cv`, as the
primary communication score for the unified Figure 4 feature observer. The
score is defined in the locked, train-normalized feature coordinate system, not
in raw image or raw pyramid-feature coordinates.

```text
For fold q:

SSE_q = sum_{n in test_q, m} (z_q[n,m] - z_hat_q[n,m])^2
SST_q = sum_{n in test_q, m} (z_q[n,m] - zbar_train_q[m])^2

R2_cv = 1 - sum_q SSE_q / sum_q SST_q
```

Here `z_n` is the fixed feature target after train-fold normalization, and
`z_hat_n` is the observer's held-out feature estimate. If `z` is z-scored or
whitened on the training fold, `zbar_train` is zero in that fold coordinate
system, so the score is a normalized negative MSE.

Interpretation and aggregation rule:

```text
R2_cv is the fraction of held-out variance recovered in the locked,
train-normalized feature space.
```

Unless otherwise stated, `R2_cv` is computed as a pooled multi-output score by
summing squared errors across held-out samples and feature dimensions. The
final cross-validated value pools out-of-fold residuals across folds using each
fold's train-mean baseline. It is not an unweighted mean of fold-level `R2`
values, and it is not an average of per-feature `R2` values. Per-feature `R2`
distributions are diagnostic summaries only.

The score can be negative. A negative value means the observer is worse than
predicting the corresponding train-fold feature mean for the held-out samples.

## Score Hierarchy

Primary:

```text
R2_cv or normalized negative MSE
```

Secondary robustness score:

```text
feature cosine
```

Feature cosine remains useful because it tests whether the recovered feature
vector points in the right direction. It should not carry the main claim by
itself, because it can ignore systematic feature-magnitude errors.

Supplement/theory score:

```text
Gaussian predictive log likelihood or Delta I_diag
```

These are useful for the probabilistic story, especially residual covariance
and nuisance-variance interpretations. They should stay secondary until the
residual variance/covariance model is itself locked, because diagonal or
shrinkage choices can dominate high-dimensional feature likelihoods.

## Locked Target Contract

The score only has a stable meaning if the feature target is fixed before the
conditions are compared.

Main target:

```text
pyramid_local_field
```

Manuscript language:

```text
pooled complex steerable-pyramid-like / oriented-pyramid feature target
```

Do not call this a Plenoptic target in the methods unless the feature target is
literally generated by Plenoptic's `SteerablePyramidFreq` in that run.

Target definition:

```text
Phi(I) = block-pooled complex steerable-pyramid coefficients

channels per band/orientation/block:
  mean Re(c)
  mean Im(c)
  mean |c|   # magnitude/amplitude, not energy

z = standardize_train(Phi(I))
```

The main target uses mean real part, mean imaginary part, and mean magnitude
`|c|`. Call the third channel "magnitude" unless it is changed to `|c|^2`; only
the squared-magnitude target should be called "energy."

Sensitivity targets:

```text
pyramid_energy_grid8
pyramid_local_field_phase_preserving_scale_balanced
```

## Unified Conditions

All main Figure 4 feature-observer conditions should be scored on this same
axis:

```text
stabilized
motion-rendered response
known-trajectory observer
zero-eye baseline
trajectory-hidden / marginal baseline
joint latent-eye observer
compact-only
compact-removed
static-PC
```

Condition labels must stay explicit:

```text
motion-rendered: trajectory used to generate the response
known-trajectory observer: trajectory explicitly available to the observer/readout
zero-eye: observer assumes no movement
trajectory-hidden / marginal: trajectory unavailable and must be ignored,
  marginalized, or inferred
joint latent-eye: observer accounts for latent trajectory structure
```

If 4B uses responses rendered under empirical trajectories but does not give
the trajectory to the decoder/readout, label it as a motion-rendered condition,
not as a known-trajectory observer.

Compact-only, compact-removed, and static-PC are subspace interventions inside
the same observer. They must be scored against the same feature target with the
same `R2_cv` definition.

This replaces the older mixed endpoint problem where 4B used diagonal
information-like scores while 4C used feature cosine, negative MSE, or image
identity depending on branch.

## Promotion Gates

Use `S = R2_cv` for the main gate.

Minimum useful-versus-nuisance gate:

```text
S_known_trajectory > S_stabilized
S_known_trajectory > S_zero
```

Joint latent-eye promotion gate:

```text
S_known > S_joint > S_zero
```

Gap-recovered summary:

```text
gap_recovered =
  (S_joint - S_baseline)
  / (S_known - S_baseline)
```

where `S_baseline` is the declared zero-eye or hidden/marginal baseline. Gap
recovered is reported only when the known-minus-baseline denominator is positive
and meaningfully above uncertainty. Always report the raw contrasts
`S_known - S_baseline` and `S_joint - S_baseline` alongside the ratio. Do not
silently cap the ratio; if it exceeds 1, report it and explain that the joint
condition exceeded the known condition under that scoring/noise realization.

## 4C Observer Status

Use the current continuous no-anchor observer as the provisional main 4C
implementation because it is audited and works on the current feature-cosine
endpoint.

Describe it as:

```text
a continuous latent-eye feature-recovery observer
```

Do not describe it as:

```text
the final ideal Bayesian observer
an estimator of the animal's true eye trajectory
```

The cleaner successor is a candidate-free linear-Gaussian/Kalman/RTS observer,
or EKF/UKF/particle-filter variant if the local-linear observation model fails.
Promote that successor only if it reproduces the known-trajectory > joint >
declared-baseline ordering on the same target and `R2_cv` score.

Catalog-search policy:

```text
Preferred main endpoint:
  continuous / candidate-free latent-eye feature recovery

Allowed support roles:
  response-cache tables for geometry calibration
  finite candidate sets for diagnostics, hard-negative stress tests, or legacy
  comparison

Avoid as main endpoint when possible:
  finite image-catalog search
  candidate-image posterior feature averaging
  trajectory-catalog replay
```

If a script uses candidate/source tables to fit a local response-vs-displacement
model, that should be described as geometry calibration, not as catalog search.
The paper-facing 4C claim should be carried by a continuous feature estimate
`z_hat`, not by choosing or averaging over a finite image candidate catalog,
unless the continuous observer fails its promotion gate.

## Implementation Audit Note

The existing BackImage feature-screen code already has useful pieces:

```text
_standardize_train_test(...)
_cross_validated_decode(...)
R2_z
decode_score_neg_mse
```

But the current helper `_mean_r2(...)` centers the denominator on the held-out
test fold mean and `_cross_validated_decode(...)` returns the mean of fold-level
`R2` values. The figure-facing `R2_cv` definition above uses pooled
out-of-fold SSE/SST and each fold's train-fold baseline:

```text
sum_test ||z_n - zbar_train||^2
```

Therefore, do not silently reuse old `R2_z` values as the final Figure 4 score.
Either recompute the score with the locked denominator or explicitly label old
values as legacy fold-centered, mean-fold `R2_z`.

## Figure Consequence

The main 4B/4C panel should be able to use one y-axis:

```text
held-out R2_cv in the locked, train-normalized,
pooled steerable-pyramid-like magnitude feature space
```

Feature cosine can appear as a robustness inset/table. Gaussian likelihood,
diagonal information, and response-residual covariance can support the theory
claim that unaccounted retinal motion appears as shared residual variability.
Noise-correlation linkage should use response residual covariance after
accounting for each eye-information condition, for example
`Cov[r - r_hat_condition]`, not covariance of feature residuals `z - z_hat`.
