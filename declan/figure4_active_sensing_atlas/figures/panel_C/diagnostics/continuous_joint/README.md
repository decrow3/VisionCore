Current readout boundary:

```text
primary endpoint: posterior expected feature recovery cosine
guardrails:       image accuracy, true-candidate posterior mass, posterior N_eff
not claimed:      direct mutual information / bits about the stimulus
```

This mirrors Wu et al.'s reconstruction-quality framing more than an infomax
framing. Wu's joint-LNBRC-dCNN analysis scored MAP image reconstructions mainly
with MS-SSIM, with LPIPS as a confirmation metric. Here we score a selected
local feature representation rather than full pixels, so the result should be
written as feature reconstruction quality.

The same diagnostic includes `known-eye` and `zero-eye` rows. Their
along-minus-across contrasts are exactly zero because those rows do not use the
axis prior to infer a trajectory: known-eye is supplied the true measured trace,
and zero-eye uses the same static trace for both axis labels. Thus the
along/across question is only meaningful for the hidden-eye joint estimator.

The confidence intervals for the paired feature contrasts cross zero at every
scale. Therefore the promoted strict continuous joint estimator does not
reproduce a clean Figure 4D-style along-contour advantage. Treat this as a
guardrail: the older 4D matched-static feature readout can support
image-conditioned useful axes, but that effect should not be automatically
projected onto the strict continuous no-start estimator.

```text

Promoted strict continuous check:
```

This is not a contradiction. The older result asks whether an axis-conditioned
trajectory prior helps a matched-static feature-posterior decoder. The newer
diagnostic asks whether the fully promoted hidden-eye continuous estimator
shows the same axis preference when it has to infer the trajectory itself. The
current answer is: keep the 4D axis result as local matched-static support, not
as a strong claim about the promoted 4C estimator.
