# Plenoptic Feature Target Cross-Check

Date: 2026-07-05

Purpose: compare the Plenoptic/Portilla-Simoncelli/steerable-pyramid feature
formulation against the current BackImage feature targets before locking the
unified Figure 4 observer target.

## Bottom Line

The current `pyramid_local_field` target is already close to the recommended
steerable-pyramid-like target:

```text
complex steerable pyramid coefficients
-> local pooling
-> real, imaginary, and magnitude channels
```

So we do not need a wholesale replacement. The important work is to lock the
definition, report it with steerable-pyramid vocabulary, use Plenoptic as a
cross-check rather than a name unless the implementation literally uses it, and
run a small sensitivity check against the main alternatives:

```text
current magnitude target:        Re, Im, |c|
energy target:                   |c|^2 only or Re, Im, |c|^2
phase-preserving target:         finer Re/Im pooling, coarser magnitude pooling
Portilla-Simoncelli statistics:  supplement only, not main target
```

The main target should remain a pooled complex steerable-pyramid-like magnitude
feature target, not full Portilla-Simoncelli texture statistics.

## What Plenoptic Says

Plenoptic describes the steerable pyramid as a multiscale oriented image
decomposition whose localized oriented filters make it useful for building
primary-visual-cortex-style models. Its Portilla-Simoncelli implementation
computes texture statistics from `SteerablePyramidFreq`, including local
autocorrelations, cross-scale correlations, cross-orientation correlations, and
local energy statistics.

The useful Plenoptic discussion for us is not "use full PS stats"; it is the
pooling recipe:

```text
compute a statistic, such as steerable-pyramid spectral energy
pool it over spatial regions
watch padding, stride, and aliasing
use multiscale pooling carefully because pyramid bands live at different scales
```

Important version detail:

```text
current repo environment: plenoptic 1.4.0
our code imports:         plenoptic.simulate.SteerablePyramidFreq
current upstream 2.x:     plenoptic.process.SteerablePyramidFreq
```

So any implementation or documentation should be version-explicit. The current
upstream README also warns that Plenoptic 2.0 introduced breaking API changes.

## What Our Current Target Does

Current source:

```text
declan/fixation_statistics_by_stimulus/run_backimage_latent_information_screen.py
```

The main target is `pyramid_local_field`, generated by `_pyramid_features`.

Preprocessing:

```text
patch -> percentile clip to 0-255-like range
      -> central crop
      -> resize local crop to 128 x 128
      -> image z-score
      -> reflect pad only if needed for even dimensions
```

Pyramid:

```text
_steerable_pyramid(patch.shape, height=4, order=3)
```

Current helper:

```text
SteerablePyramidFreq(
  image_shape,
  height=height,
  order=order,
  is_complex=True,
  downsample=False,
  tight_frame=False,
)
```

Feature extraction:

```text
for each complex pyramid band and orientation:
  real = Re(c)
  imag = Im(c)
  mag  = |c|

  local feature vector =
    block_mean(real),
    block_mean(imag),
    block_mean(mag)
```

The current default target therefore keeps coarse signed phase-sensitive
features through pooled `Re` and `Im`, plus local amplitude/magnitude through
pooled `|c|`.

## Current Alternatives Already In The Code

These alternatives already exist and should be treated as target-sensitivity
options rather than new concepts:

```text
pyramid_local_field_phase_preserving
  finer Re/Im pooling plus coarser magnitude pooling

pyramid_local_field_phase_preserving_scale_balanced
  same, with scale-balancing weights

pyramid_energy_global
pyramid_energy_grid4
pyramid_energy_grid8
  pooled |c|^2 energy targets

pyramid_local_stats_energy_orientcov
pyramid_energy_orientcov_grid4_typebalanced
pyramid_energy_orientcov_grid8_typebalanced
  energy plus orientation-covariance local statistics
```

Full `PortillaSimoncelli` is not currently the main target, and should not be
promoted as the main Figure 4 target unless the claim changes from local
feature recovery to texture-statistic recovery.

## Important Differences To Check

| Detail | Plenoptic/PS reference point | Current method | Scientific consequence |
|---|---|---|---|
| API version | Plenoptic 2.x uses newer `process` API; docs warn of breaking changes | Environment is Plenoptic `1.4.0`, using `plenoptic.simulate` | Lock version/provenance before reproducing or comparing targets |
| Transform | `SteerablePyramidFreq`, complex coefficients available | Same family, via helper wrapper | Good alignment |
| Pyramid normalization | Plenoptic examples vary; PS uses `tight_frame=False`, some pooling examples use `tight_frame=True` | Current helper uses `tight_frame=False` | Keep for continuity; run `tight_frame=True` sensitivity only if feature target becomes contested |
| Downsampling | Default Plenoptic pyramid can downsample by scale | Current helper uses `downsample=False` | Our bands stay on common spatial grid; easier block pooling, but not identical to multiscale downsampled examples |
| Main statistic | PS emphasizes magnitude/energy correlations and higher-order stats | Main target uses pooled `Re`, `Im`, and `|c|` | More local and phase-sensitive than PS; good for feature recovery, less texture-statistic-like |
| Energy definition | Plenoptic discussion examples use spectral energy `|c|^2` | Main target uses magnitude `|c|`; energy variants exist | Decide whether canonical target is `|c|` or `|c|^2`; energy aligns better with complex-cell language |
| Pooling | Plenoptic discussion recommends Gaussian/convolutional pooling and warns about stride/aliasing | Current target uses non-overlapping block means | Block pooling is simple and auditable; Gaussian pooling would be smoother but is a new target |
| Padding | Plenoptic discussion notes padding affects border artifacts; examples use circular padding for convolution | Current method reflect-pads odd dimensions, but block pooling after resizing mostly avoids convolutional border policy | Fine for current block target; document explicitly |
| Scale balancing | PS/Plenoptic statistics have structured scale bookkeeping | Current phase-preserving scale-balanced target exists; default target may overweight bands by dimensionality | Use fold z-scoring/PCA and/or scale-balanced sensitivity |

## What To Lock For The Unified Observer

Recommended canonical target for the unified Figure 4 observer:

```text
pyramid_local_field
```

with an explicit definition:

```text
Phi(I) = block-pooled complex steerable-pyramid-like coefficients

channels per band/orientation/block:
  mean Re(c)
  mean Im(c)
  mean |c|   # magnitude/amplitude
```

This is the most continuity-preserving choice because it is already used by the
current 4B, 4C, and 4D branches.

Primary sensitivity target:

```text
pyramid_energy_grid8 or pyramid_energy_grid4
```

This tests the Plenoptic-discussion / complex-cell version:

```text
mean |c|^2
```

Only the squared-magnitude sensitivity should be called an energy target. The
main `pyramid_local_field` target should be called a magnitude/amplitude target.

Secondary sensitivity target:

```text
pyramid_local_field_phase_preserving_scale_balanced
```

This tests whether coarse block pooling of signed phase is suppressing useful
phase information or over-weighting particular scales.

Supplement-only target:

```text
Portilla-Simoncelli-style stats
```

Use only if we explicitly want a texture-statistic sensitivity. Do not make it
the main target for the unified feature observer.

## Required Check Before Re-Running

Before a new unified 4B/4C production run, emit a small feature-target audit:

```text
target_name
plenoptic_version
steerable_pyramid_import_path
image_preprocessing
resize_px
height
order
is_complex
downsample
tight_frame
pooling_type
pooling_grid_or_kernel
channels
feature_dim_before_pca
feature_dim_after_pca
fold_zscore
fold_pca
```

This prevents the target from becoming another hidden moving part.

## Practical Verdict

Use Plenoptic as a sanity check, not as a reason to restart and not as a method
name unless the run literally uses Plenoptic.
Our current target already matches the lean recipe well enough for the main
story, but we should make two details explicit:

1. The main target uses magnitude `|c|`, not energy `|c|^2`.
2. The current pooling is block pooling, not Gaussian/convolutional pooling.

If a single sensitivity run is affordable, prioritize:

```text
pyramid_local_field
vs
pyramid_energy_grid8
vs
pyramid_local_field_phase_preserving_scale_balanced
```

all under the same unified known/zero/joint feature-recovery score.
