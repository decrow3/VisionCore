# Free-Viewing Latent-Information FEM Test Plan

Last curated: 2026-06-15.

This plan turns the general `I_z(tau)` framework into an executable sequence of
analyses for natural-image/free-viewing FEMs. It assumes the Vernier work is the
clean scalar proof of concept and asks whether the same information objective
can explain BackImage drift geometry once the latent visual variable `z` is
made explicit.

## Core Question

For a local BackImage patch `I_i`, candidate retinal trajectory `tau`, and
explicit latent visual feature vector `z_i = phi(I_i)`, does the V1 twin response
under `tau` contain information about `z_i` in a way that predicts real
fixational eye movement geometry?

The objective is:

```text
U_z(tau) = I(z; r_tau)
```

where `r_tau = F_theta(I, tau)` is the V1 population response generated by the
digital twin.

Every analysis must also report incremental information relative to static
sampling:

```text
Delta U_z(tau) = U_z(tau) - U_z(static)
```

and axis-relative information:

```text
Delta U_z_axis(tau) = U_z(tau) - U_z(random-axis matched control)
```

These quantities answer different questions:

- high `U_z(tau)`: the trajectory preserves or represents the local feature
  latent;
- positive `Delta U_z(tau)`: the trajectory adds recoverable information beyond
  static sampling;
- negative `Delta U_z(tau)`: the trajectory disrupts information about `z`;
- positive `Delta U_z_axis`: the axis or path is better than a matched random
  motion, independent of absolute feature decodability.

The practical test is not whether a model objective can rediscover raw edge
geometry. Raw edge is already the benchmark. The model earns explanatory value
only if an explicit `z` objective:

- beats raw edge as a predictor of drift geometry,
- predicts where raw-edge alignment is strongest,
- predicts deviations from raw edge,
- predicts drift anisotropy or scale,
- and survives within-session patch/axis shuffles.

## Unit-Space Policy

Use the unit-space provenance ledger before interpreting any population result.

For free-viewing population-geometry claims:

- Preferred: full canonical population, if computationally feasible.
- Acceptable first pass: repeated large canonical population samples, e.g.
  `N = 256` with multiple seeds.
- Smoke only: `N = 16`.
- Do not make strong population-geometry claims from the 16-channel matched
  center space.

For each run, record:

- checkpoint path,
- unit/sample count,
- random seed,
- reliable-unit threshold,
- whether the population is full canonical, sampled canonical, or matched
  comparison space.

## Stage 1: Define External Latent Feature Families `z`

Goal: define non-self-referential visual latents `z_i = phi(I_i)` for each local
BackImage patch.

Each feature family should be represented in two latent scopes:

1. Center latent
   - `z_center = phi(I_center)`.
   - Features are measured at or near the fixation center.
   - This tests whether motion preserves or improves information about the
     currently selected foveal feature.

2. Local-field latent
   - `z_field = phi(I_local)`.
   - Features describe the local neighborhood or patch field, e.g. PCA/DCT/Gabor
     coefficients over the patch.
   - This tests whether motion samples a spatial feature field rather than only
     preserving the center representation.

Both are needed because a candidate movement can be useless for a point feature
but useful for a local field. The first pass should keep the scopes separate in
all filenames and summaries.

Feature families, in order of priority:

1. Oriented local filter coefficients
   - Gabor or steerable-pyramid amplitudes and phases.
   - Multiple orientations and spatial frequencies.
   - Primary candidate because it aligns naturally with edge/phase hypotheses.

2. DCT or Fourier local coefficients
   - Low/mid/high spatial-frequency bands.
   - Compact and cheap.
   - Useful for testing whether generic local frequency content, not edge
     orientation specifically, is the relevant latent.

3. Local phase and edge-position latents
   - Phase of oriented filters near the dominant local edge axis.
   - Edge offset relative to patch center.
   - Closest free-viewing analogue of Vernier/fine-position `z`.

4. Salience or priority features
   - Contrast, orientation contrast, edge density, high-SF power, feature
     surprise, local saliency-map coefficients.
   - Use as a candidate only if implemented with a fixed external transform,
     not a twin-derived target.

5. Twin-core feature latents
   - Internal core/ConvGRU features from the digital twin.
   - Treat as a model-internal hypothesis, not an independent biological target.
   - Run after external feature families.

For each feature family:

- Store raw feature vector.
- Store standardized feature vector.
- Store PCA-reduced versions, e.g. `k = 4, 8, 16, 32`.
- Store feature-whitened versions for decoding, so high-variance coefficients do
  not dominate ridge `R2`.
- Store feature reliability/coherence measures.
- Store feature-axis summaries when applicable.
- Store latent scope: `center` or `local_field`.

Output:

```text
outputs/fixation_statistics_by_stimulus_all_sessions_after_review/backimage_latent_features/
  latent_features_by_window.csv
  latent_feature_metadata.json
  latent_feature_diagnostics/
```

Decision gate:

Proceed only for feature families with stable distributions, no obvious
registration artifacts, enough across-window variance within session, and
nondegenerate PCA spectra after standardization.

## Stage 2: Candidate Motion Library

Goal: build a standard candidate set `tau` for each patch before estimating
information.

Axis comparisons must use matched counterfactual trajectories. For the standard
axis screen, the candidates differ only in axis. They must share:

- amplitude type,
- amplitude value,
- duration,
- temporal template,
- number of samples,
- and path-length/motor-cost convention.

Do not compare raw measured traces against idealized edge/random axes unless the
analysis is explicitly testing real trace shape or real amplitude.

Primary candidates:

- static center,
- real drift axis rendered as the same matched template as all other axes,
- raw edge axis,
- edge-orthogonal axis,
- raw gradient axis,
- raw spectrum axis,
- random axes,
- fixed grid axes, e.g. every `15 deg`,
- optional recorded trace snippets matched by amplitude/duration for a separate
  trace-shape analysis.

Every motion candidate must explicitly record:

```text
amplitude_type: endpoint | RMS radius | path length | diffusion scale
amplitude_value_deg
duration_s
template_shape
n_timepoints
axis_deg
path_length_deg
rms_radius_deg
endpoint_extent_deg
```

Scale candidates for the matched-axis screen:

- `0 deg`,
- biologically matched values from the observed window distribution:
  `0.25x`, `0.5x`, `1.0x`, and `2.0x` observed RMS radius,
- fixed endpoint/RMS values only after explicitly naming the amplitude type,
  e.g. `endpoint = 0.0625 deg`, `endpoint = 0.125 deg`, `endpoint = 0.25 deg`,
- matched observed RMS or path length,
- larger stress-test scales only after the first pass.

The fixed values above are not interchangeable with diffusion-scale values.
`0.125 deg` means `7.5 arcmin`; that may be reasonable for endpoint extent but
large for RMS radius. The run metadata must make this explicit.

Trajectory shape candidates:

- endpoint displacement,
- sinusoidal line segment,
- phase-cloud samples,
- order-shuffled real trace,
- matched random trace.

Separate analyses:

- axis-only: matched template rotated into each axis;
- scale-only: fixed axis with amplitude sweep;
- trace-shape: measured trace, order-shuffled trace, and matched random trace;
- full real-trace test: raw observed amplitude and temporal structure.

## Stage 4: Estimate `I_z(tau)`

Goal: estimate how informative the twin response under each candidate trajectory
is about each latent feature family.

First-pass estimators:

1. Cross-validated ridge decoding
   - Predict `z_i` from `r_tau`.
   - Use held-out windows within session and held-out sessions.
   - Use nested regularization selection inside the training split.
   - Use PCA-reduced and feature-whitened `z` targets with fixed `k`.
   - Report `R2`, explained variance, rank-normalized variants, and
     `Delta R2` relative to static and random-axis baselines.
   - Treat ridge as the first screen, not the final information estimator.

2. Linear-Gaussian information approximation
   - Estimate:

```text
0.5 * log det(I + C_z B_tau^T Sigma^-1 B_tau)
```

   - Use shrinkage covariance.
   - Compare with ridge `R2` to avoid overinterpreting one estimator.

3. Fisher/local perturbation estimator
   - Use only for scalar or low-dimensional latents such as edge offset,
     local phase, or Vernier-like position.

Observer variants:

- pose-aware: decode from responses with known candidate phase/time label,
- pose-blind: decode after marginalizing or pooling over phase/time,
- pose-uncertain: add Gaussian uncertainty over retinal pose before decoding.

Normalization variants:

- raw information,
- static-relative information:
  `Delta U_z(tau) = U_z(tau) - U_z(static)`,
- random-axis-relative information:
  `Delta U_z_axis = U_z(tau) - U_z(random-axis matched control)`,
- per-spike or per-mean-rate normalized information,
- motion-cost-normalized information.

Required first-pass score columns:

```text
U_z
Delta_U_z_vs_static
Delta_U_z_vs_random_axis
R2_z
Delta_R2_z_vs_static
Delta_R2_z_vs_random_axis
pose_gap = U_z_pose_aware - U_z_pose_blind
```

Output:

```text
outputs/fixation_statistics_by_stimulus_all_sessions_after_review/backimage_latent_information_scores/
  information_by_window_candidate_z.csv
  information_summary_by_z_candidate.csv
  pose_gap_summary.csv
```

Decision gate:

The estimator is usable only if:

- static and random-axis baselines are well behaved,
- held-out performance is above chance for at least one `z`,
- pose-aware and pose-blind variants differ in interpretable directions,
- results are not dominated by firing rate, target-feature variance, or motion
  scale,
- nested regularization and held-out session evaluation do not reverse the main
  sign.

## Stage 5: Biological Geometry Tests

Goal: ask whether `I_z(tau)` explains real drift geometry.

All tests should be run separately for:

- absolute information `U_z`,
- static-relative information `Delta U_z_vs_static`,
- random-axis-relative information `Delta U_z_vs_random_axis`,
- and pose gap.

Primary comparisons:

1. Axis preference
   - Does `argmax_tau U_z(tau)` align with real drift better than random?
   - Does it beat raw edge?

2. Real-versus-baseline information
   - `U_z(real drift axis)` versus `U_z(random axis)`.
   - `U_z(real drift axis)` versus `U_z(raw edge axis)`.
   - `U_z(raw edge axis)` versus `U_z(edge-orthogonal axis)`.
   - Repeat these comparisons for `Delta U_z_vs_static`.

3. Alignment-strength prediction
   - Does `U_z(edge axis) - U_z(edge-orthogonal axis)` predict
     `cos2(real drift axis, edge axis) = cos(2 * (theta_real - theta_edge))`?
   - Does it predict this beyond raw edge coherence and pixel stability
     advantage?
   - Repeat with `Delta U_z(edge) - Delta U_z(edge-orthogonal)`.

4. Residual geometry prediction
   - Does `argmax_tau U_z(tau)` predict deviations of real drift from raw edge?
   - Does information advantage predict drift anisotropy?
   - Does information advantage predict drift scale or diffusion?

5. Session generalization
   - Train feature/information weighting on held-out sessions.
   - Evaluate drift-geometry prediction on held-out sessions.

Required summary statistics:

- session-level mean `cos2`,
- weighted session-level mean `cos2`,
- sign counts across sessions,
- paired deltas versus raw edge,
- bootstrap confidence intervals over sessions,
- within-session patch/axis shuffle p-values,
- across-session shuffle p-values,
- held-out session performance.

Output:


Preservation-versus-sampling decision table:

| Outcome | Interpretation |
| --- | --- |
| high `U_z` but low or negative `Delta U_z_vs_static` | movement preserves the local feature representation but does not add information beyond static |
| positive `Delta U_z_vs_static` | movement adds recoverable information about `z` beyond static sampling |
| pose-aware positive, pose-blind negative | feature information exists but requires retinal pose |
| edge axis preserves `U_z`, orthogonal disrupts it | edge-parallel drift may protect the selected feature representation |
| real axis improves `U_z` or `Delta U_z` beyond raw edge | model objective explains more than simple image geometry |
| `I_z` chooses raw edge but does not predict when edge matters | the objective is mostly rediscovering image geometry |

Decision gate:

Strong positive:

- a `z` objective beats raw edge,
- survives within-session shuffles,
- generalizes across sessions,
- and predicts at least one additional biological metric such as anisotropy or
  scale.

Moderate positive:

- no beat over raw edge, but `I_z` predicts where raw-edge alignment is strongest
  beyond raw edge coherence and pixel stability.

Useful negative:

- no `z` objective beats raw edge or predicts alignment strength.

Pose-only:

- pose-aware information works, pose-blind collapses.
- Interpret as phase-dependent information requiring pose knowledge, consistent
  with Vernier.

## Stage 6: Compare `z` Families

Goal: rank candidate latents by explanatory value.

Ranking criteria:

1. Biological geometry prediction
   - beats raw edge or predicts raw-edge alignment strength.

2. Statistical robustness
   - survives within-session shuffles,
   - survives held-out sessions,
   - has consistent signs across sessions.

3. Observer interpretability
   - pose-aware and pose-blind variants behave sensibly,
   - pose gap is not the whole result unless that is the intended conclusion.

4. Nontriviality
   - not just high firing rate,
   - not just edge coherence,
   - not just pixel stability,
   - not just maximal motion.

5. Simplicity
   - prefer external low-level features over twin-internal `z` if performance is
     comparable.

Output:

```text
outputs/fixation_statistics_by_stimulus_all_sessions_after_review/backimage_latent_information_z_comparison/
  z_family_ranked_summary.csv
  z_family_decision_table.md
```

## Stage 7: Optimized and Adversarial Trajectories

Run this stage only after at least a moderate-positive `z` result.

Goal: optimize trajectories under a chosen `z` objective and compare optimized,
real, random, raw-edge, and adversarial trajectories.

Objective:

```text
tau_star = argmax_tau U_z(tau) - C(tau)
tau_bad  = argmin_tau U_z(tau) + C(tau)
```

Costs:

- RMS displacement,
- path length,
- velocity,
- acceleration,
- fixation-window violation probability,
- pose gap or pose covariance burden.

Required comparisons:

- optimized versus real,
- real versus random,
- raw edge versus optimized,
- random versus adversarial,
- pose-aware versus pose-blind optimized trajectories.

Decision gate:

Continue only if:

- optimized is better than real/random under the stated `z`,
- adversarial is worse than random,
- optimized geometry is biologically plausible,
- and the objective still predicts observed drift geometry.

Stop if optimized does not beat raw edge or if adversarial is not meaningfully
worse than random.

## Manuscript Claim Boundaries

Do not claim:

- free-viewing FEMs are globally optimal,
- raw edge alignment is explained by the twin unless the `z` objective beats or
  improves on raw edge,
- generic stability, whitening, or activity is the active-sensing objective,
- pose-aware information alone implies downstream pose-blind usability.

Do claim, if supported:

- Vernier is the clean scalar `I_z(tau)` case,
- free viewing requires an explicit hypothesis for `z`,
- raw edge is the current strongest BackImage baseline,
- generic twin stability is insufficient as an axis optimizer, but signed
  edge-parallel preservation is robust across pixel and twin metrics,
- a successful `z` objective identifies which local visual information real
  drift may be preserving or sampling.

If no `z` objective works, the fair conclusion is:

```text
The Vernier task shows that I_z(tau) is useful when the latent is known. In
free viewing, current tested latents do not yet explain drift geometry beyond
raw local image edge structure.
```
